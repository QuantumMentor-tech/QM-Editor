# QM Editor — LSP Completion Safety & Acceptance Governance

## Phase 06 — Advanced Features (Step 58 of 135)

---

# 1. Core Safety Principles

LSP completion involves executing text edits generated by an external, potentially untrusted child process. To guarantee document integrity and user trust, QM Editor enforces four non-negotiable safety boundaries:

1. **Document Authoritativeness**: The language server suggests text; QM Editor alone validates and applies it.
2. **Atomic Edit Transactions**: No partial edits or direct buffer writes are permitted. All changes pass through `EditorCoordinationService.applyTransaction()`.
3. **Stale Context Invalidation**: Outdated completions generated against past document revisions or switched tabs are discarded.
4. **Read-Only & Workspace Isolation**: Suggestions cannot mutate read-only files, write outside workspace boundaries, or execute arbitrary filesystem actions.

---

# 2. Acceptance Verification Gates

Before any completion edit is applied to a document buffer, it must pass five sequential verification gates:

```text
User Accepts Completion
           ↓
[Gate 1: Document Existence & Workspace Check]
           ↓
[Gate 2: Read-Only Enforcement]
           ↓
[Gate 3: Revision & Model Freshness Check]
           ↓
[Gate 4: Range & Non-Overlapping Edit Check]
           ↓
[Gate 5: Atomic Edit Transaction Execution]
           ↓
Buffer Mutated + Revision Advanced + Undo History Recorded
```

### Gate 1: Document Existence & Workspace Check
- Verifies that the document ID matches an active record in `DocumentEngine`.
- Verifies that the workspace ID hasn't switched during completion selection.

### Gate 2: Read-Only Enforcement
- Inspects `doc.metadata.isReadOnly`.
- If the file is locked, marked read-only on disk, or in conflict, completion insertion is aborted with `reason: 'read_only'`.

### Gate 3: Revision & Model Freshness Check
- The completion request records the document's content revision at invocation (`doc.contentRevision`).
- If the user typed another character, pasted text, or formatted the document before acceptance, the expected revision will not match the current revision.
- The edit is rejected with `reason: 'stale'`.

### Gate 4: Range & Non-Overlapping Edit Check
- Ranges are verified against buffer bounds: `0 <= from <= to <= doc.content.length`.
- If `additionalTextEdits` are present, they are verified to ensure no edits overlap with one another or with the primary replacement range.

### Gate 5: Atomic Edit Transaction Execution
- The edit is packaged into a `ProgrammaticEditTransaction` with `source: 'completion'`.
- `EditorCoordinationService` and `DocumentEngine` update the buffer atomically.
- A single undo entry is recorded so that pressing `Ctrl+Z` / `Cmd+Z` restores the original text in one stroke.

# 3. Security & Sanitization

1. **Documentation Sanitization**:
   - Strips `<script>`, `<iframe>`, `<object>`, `<embed>`, `<meta>`, and `<link>` tags.
   - Neutralizes `javascript:` URIs.
   - Truncates oversized documentation to 10,000 characters.

2. **Command Metadata Isolation**:
   - LSP items may carry arbitrary `command` payloads.
   - QM Editor does **not** automatically execute arbitrary server commands on completion acceptance.
   - Command metadata is quarantined to prevent untrusted shell or process execution.

3. **Defensive Response Clamping**:
   - Maximum item count is capped at `lsp.completion.maxItems` (default 500, clamped between 10 and 2000).
   - Protects the UI from pathological language server payloads and memory exhaustion.
